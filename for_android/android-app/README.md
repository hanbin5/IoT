# Android 센서 수집 앱

Android 8.0(API 26) 이상에서 실행한다. Android Studio에서 이 폴더를 연다. SDK Manager에서 Android SDK Platform 35를 설치하고 Gradle JDK 17, Gradle 배포판 8.9를 선택한다. Wrapper가 포함되어 있지 않으므로 로컬 Gradle 8.9를 지정하거나 이 폴더에서 설치된 Gradle 8.9로 아래 명령을 실행한다.

    gradle wrapper --gradle-version 8.9
    ./gradlew assembleDebug

Windows에서는 두 번째 명령을 gradlew.bat assembleDebug로 실행한다. Android Studio의 Run으로 USB 디버깅을 켠 휴대전화에 설치할 수 있다.

## 독립 실행 및 CSV 저장

한 번 설치한 뒤 USB를 분리하고 앱 목록의 **센서 수집**을 실행한다. 서버 전송을 끄고 수집 시작 → 중지를 누르면 네트워크 없이 측정된다. 1초 단위로 앱 전용 SQLite에 저장하고 정상 중지 시 마지막 묶음도 저장한다. 강제 종료 시 아직 기록되지 않은 마지막 묶음은 유실될 수 있다. 내보내기 버튼으로 전체 기록을 다운로드 폴더 등에 ZIP으로 저장한다. ZIP 안의 각 세션에는 meta.json 및 센서별 CSV가 있다. 앱 삭제 또는 앱 데이터 초기화 전에 내보낸다.

## 네트워크를 통한 전송

같은 사설 Wi-Fi의 PC에서 프로젝트 루트 기준 `py web-sensor/server.py --host 0.0.0.0`을 실행한다. `ipconfig`에서 활성 네트워크 어댑터의 IPv4 주소를 확인한다. 예를 들어 주소가 192.168.0.23이면 휴대전화 브라우저에서 http://192.168.0.23:8000/app 을 열어 {"ok": true}를 확인한다. 앱에서 서버 전송을 켜고 같은 주소를 입력한 뒤 측정을 시작한다. 이 서버는 인증이 없으므로 신뢰하는 사설망에서 사용한다. 외부에서는 기존 Tailscale HTTPS /app 주소를 사용할 수 있다.

측정 시작 시 선택한 전송 여부와 주소는 세션에 저장된다. 전송을 켜면 휴대전화 원본을 보관하면서 WorkManager가 연결 가능한 네트워크(모바일 데이터 포함)에서 미전송 묶음을 순서대로 전송한다. 연결이 끊겼거나 서버가 꺼져 있으면 지수 백오프로 재시도한다. 네트워크가 복구되어도 OS 스케줄에 따라 지연될 수 있다. 로컬 전용 세션은 자동 전송되지 않는다. PC 서버는 전송할 때만 필요하다. 새 서버는 재시도한 묶음을 중복 저장하지 않는다.

## 데이터 해석

- 가속도계 이벤트를 기준으로 약 100 Hz를 요청한다. 보조 센서는 비동기로 도착하므로 각 행에는 가장 최근에 수신한 값을 사용한다. 실제 속도는 화면에서 확인한다. 없는 보조 센서는 빈 CSV 칸으로 남긴다.
- acc와 grav는 Android 가속도에서 중력 분리 후 부호를 바꾼 m/s² 값이다. 화면을 위로 놓고 정지하면 grav_z는 약 −9.81이고 acc는 0에 가깝다. 전용 중력 센서가 없으면 가속도 저역통과 추정치를 사용한다. gyro는 rad/s, mag는 µT이고 mag_accuracy는 −1~2다.
- quat는 Android rotation vector의 기기→동·북·상향 기준 회전(w,x,y,z)이다. iOS의 임의 수평 기준과 방위각 원점이 다르므로 플랫폼 간 절대 yaw 비교에는 기준 정렬이 필요하다.
- 기압은 약 1 Hz의 hPa, 상대 고도는 첫 기압 기준 m, 시간은 센서 이벤트 시각을 변환한 Unix epoch ns다. 에뮬레이터는 가상 센서 입력을 사용한다.
- 이 단계는 iOS 앱과 같은 원시 데이터 수집 단계다. 활동 분류와 층 판정은 후속 분석에 해당한다.
